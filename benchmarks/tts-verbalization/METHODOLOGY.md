# Methodology

How this experiment was run, in enough detail to argue with. The findings are in
[README.md](README.md); this file is the method behind them.

## What is being measured

Whether a text-to-speech model produces the correct spoken form of a non-standard
written token. Not audio quality, not naturalness, not speaker similarity.

Each item is a full carrier sentence containing one non-standard span:

```
written  The event is scheduled for 05/20/2023 at the main hall.
spoken   The event is scheduled for May twentieth twenty twenty three at the main hall.
```

The model is given the written form. The audio is transcribed. The score asks
whether the transcript contains a correct reading of the **span that changed**, not
of the whole sentence.

## Why the score is target-based, not whole-sentence

An early version scored whole-sentence agreement and it measured the recognizer more
than the voice. A recognizer writing "DEAD LINE" for "deadline" failed an item whose
verbalization was perfect.

`canonicalize.py` therefore does a **surface diff** between the written and spoken
forms to locate the span that changed, and scores only that span:

```
"Let's meet at 10:30 tomorrow."   ->  target: "ten thirty"
"The price is $10.99."            ->  target: "ten dollars and ninety nine cents"
```

The diff is on surface tokens, not canonical ones. Canonicalization deliberately
treats `10:30` and "ten thirty" as equal, so a canonical diff reports no target for
over half the corpus: it erases the very transformation under test.

## Reading equivalence

A correct reading has many surface forms. `canonicalize.py` builds the set of
acceptable canonical token sequences for a span and asks whether any of them is
present in the transcript. It handles:

- number words and English number grammar (`"one thousand two hundred thirty four"`)
- symbol readings, several per symbol where genuinely ambiguous
  (`-` is "dash", "hyphen", silent, "to" in a score, "minus" in a sum)
- currency expansion (`$10.99` -> "10 dollars 99 cents")
- abbreviations, both spelled and expanded (`kg` -> "kilograms")
- Roman numerals, fractions, ordinals
- digit-run merging, for identifier categories only

Digit merging is deliberately restricted. With it on everywhere, "two zero two three"
would match "twenty twenty three", and reading a year digit by digit is exactly the
failure this experiment exists to catch.

## Items that cannot discriminate are excluded

If the written and spoken forms canonicalize to the same token multiset, the item
cannot tell a correct rendering from a wrong one. `has_target()` detects this and the
item is excluded and counted, never guessed at.

The corpus generator applies the same test at generation time, so no such item
reaches the published set.

## Screening runs before scoring, never after

If synthesis failed, produced near-silence, or the recognizer hallucinated fluent
text over nothing, edit distance is measuring a category error rather than
intelligibility. `screen.py` checks before scoring:

| check | rule |
|---|---|
| too short | under 0.20 s |
| implausibly long | over 0.60 s per character of written text |
| silent | RMS below 1e-4 |
| empty transcript | no tokens |
| hallucination suspect | transcript over 2x the reference token count |

A screened item is reported as its own outcome and excluded from the score. Averaging
failures into the metric is how a broken pipeline looks like a merely mediocre voice.

In this run, 22 records were screened: 13 empty transcripts and 9 hallucination
suspects.

## The corpus

1,080 sentences, 27 categories, 40 each, generated by `gen_corpus.py` from
`data/spec/en.yaml` and a seed. Generation is **programmatic, not model-written**:
each category has a generator that produces the written form and its correct spoken
form from the same structured value, so the reference reading is correct by
construction. No model guessed at an answer and no human adjudicated a judgement
call.

Candidates are rejected unless all four hold:

1. `has_target()` — the forms genuinely differ, so the item discriminates
2. the reference reading scores as correct against the scorer
3. a deliberately corrupted reading scores as **wrong**, so the item detects an error
4. the spoken form is short enough relative to the carrier that screening will not
   reject correct audio

Check 3 is the one that matters. Without it an item can pass everything and still be
unable to fail a wrong answer.

Rejects are written to a rejects file with their reason rather than dropped silently.
Filtering on the current canonicalizer selects for transformations it already
understands, so a blind spot would otherwise delete a whole category with nothing in
the output saying so. The published run had zero rejects.

Carrier sentences are full sentences by design. Screening rejects audio longer than
0.60 s per character of **written** text, so a bare fragment like `$1,234,567.89`
(13 characters, a 7.8 s ceiling) would throw out correct audio in exactly the
high-expansion categories the experiment exists to measure.

### Regenerating it

```bash
python gen_corpus.py --locale en-US
```

Deterministic. Same seed, same corpus, byte-identical, on any operating system.

## Scoring

`score.py` reports, per model:

- **match rate** — fraction of scored clips containing a correct reading of the target
- **95% CI** — percentile bootstrap, 1,000 resamples, fixed seed, order-independent
- **mean WER** — whole-sentence word error rate, as a secondary signal
- **excluded** — screened and errored clips, counted by reason, never folded into the rate

Denominators count **scored** clips, not attempted ones. A model that failed to
generate is not a model that spoke incorrectly.

The bootstrap sorts its input before resampling. It draws by index from a fixed seed,
so without that the interval depended on the row order of the input file: sorting
`results.jsonl` by key shifted every published CI. An interval has to be a property
of the sample, not of the file.

## Two recognizers

A single recognizer deciding what a model "said" is a weak foundation, and
arXiv:2607.08256 reports TTS rankings reversing across recognizer families. Every
clip went through two.

**OpenAI whisper-1 is the scorer.** It passed a validation gate against blind human
listening on a stratified sample.

**Deepgram nova-3 is a cross-check, never a scorer.** It failed the same gate: its
language model expands abbreviations, turning "mph" into "miles per hour", which
repairs a real verbalization failure into a pass. `numerals=false` stops digit
formatting but not lexical expansion. `score.py` refuses to average the two lineages;
they are two measurements of the same audio, not more samples of one.

In this run the two rank all seven models identically, and disagree on 832 of 7,497
clips scored by both (11.1%). Every contested clip is in
`results/recognizer-disagreements.csv` with what each recognizer heard.

## Running it

Models are called through Replicate, pinned by version hash (recorded in
`results/manifests/`). Recognizers are HTTP APIs. Nothing runs locally, so the
machine barely matters: the time is spent waiting on sockets.

`run.py` is resumable and append-only. Audio is cached by content hash and
transcripts by (wav, recognizer), so a re-run costs only what was missing. A run that
dies mid-flight is restarted with the same command.

The published run was sharded by model across 7 processes
(`deploy/shard_by_model.sh`) on a single small cloud instance.

## What this cannot tell you

- **It is not a word error rate.** Every sentence is chosen to be hard.
- **These are models as packaged on Replicate**, not bare checkpoints. Wrapper
  configuration measurably changes results.
- **English only.**
- **The hashtag convention is ours.** The reference reading includes the symbol.
- **Compute figures come from 10 clips per model**, not the scored run.
- **69 of 15,120 records (0.5%) never produced a score** and are excluded.

## Files

| file | what it does |
|---|---|
| `gen_corpus.py` | generates the corpus from the spec and a seed |
| `canonicalize.py` | target extraction and reading equivalence: the metric |
| `screen.py` | the checks that run before scoring |
| `run.py` | the driver: resumable, cached, per-item isolation |
| `score.py` | rates, bootstrap CIs, exclusion accounting |
| `disagree.py` | cross-recognizer disagreement |
| `audit.py` | blind listening audit (needs audio, which is not published) |
| `verify.py` | Tier 1: recomputes every published number |
